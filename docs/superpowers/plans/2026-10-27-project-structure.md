# 项目结构整理

用户选择适度重构并授权直接实施。

目标：让服务、离线工具、测试、示例与文档各有归属，保持 API 路径、数据库表结构及业务处理逻辑。
采用现有 backend 包，不引入 src 布局、依赖或通用服务层。

- [x] 将 router.py 拆为 api/auth.py、chat.py、longtext.py、records.py；认证依赖放 api/dependencies.py，令牌与密码工具放 security.py，ORM 模型放 models.py。
- [x] 响应处理与长文运行器配置放 services/，离线工具放 tools/，旧示例放 examples/，测试放根目录 tests/。
- [x] 统一 backend 包导入与根目录启动，固定日志和在线生成结果的项目内位置，修正环境变量示例。
- [x] 使用说明移入 docs/，补根 README，更新工具命令，删除两个已确认的空文件。
- [x] 检查迁移前后路由及定义，运行单元测试、CLI 帮助、语法和 diff 检查。

风险与边界：工具 Python 导入和命令路径改变，文档提供对应关系；不保留无人调用的旧入口包装。数据库不迁移，不调用外部模型。已有运行依赖不完整，无法据静态检查宣称服务端到端可用。旧 run_SLL.py 参数失配仅归档说明。

验证结果：24 项测试中 18 项通过、6 项真实训练测试按默认配置跳过；3 个工具的 --help 可独立执行；语法与 diff 检查通过。原 router.py 的全部 15 个函数/类 AST 保持一致；7 个迁移实现除导入路径外 AST 保持一致。日志路径通过临时目录实测。独立复查未发现新增回归。未执行 API/数据库/模型集成验证，原因是当前环境缺少原项目运行依赖。
