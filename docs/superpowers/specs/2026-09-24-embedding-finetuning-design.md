# Embedding 离线微调设计

## 目标与范围

用户已确认：实现离线微调，使用 Sentence Transformers 全参数对比学习，
输入 JSONL 查询/相关文档对，输出模型、训练配置与训练前后检索指标。
默认基础模型为 `nomic-ai/nomic-embed-text-v1.5`，允许指定其他兼容模型。

当前在线检索由 `backend/init.sql` 中的 pgai/Ollama 提供。本次增加独立命令行
训练入口，不修改数据库、在线检索或 Web 服务。模型文件首次使用时需要下载；
已缓存或指定本地模型目录后可离线训练。

## 方案

采用 Sentence Transformers 原生 Trainer、MultipleNegativesRankingLoss 和
检索评估器。复用库的训练、设备选择与模型序列化能力。
与 LoRA 相比，全参数微调省去适配器配置与合并流程，但训练显存开销更大；
可通过减小 batch size 和最大序列长度控制开销。

交付训练脚本、独立训练依赖文件、中文使用说明以及一个轻量测试文件。
训练依赖安装在单独虚拟环境中，不加入后端服务的 requirements.txt。

## 输入与校验

训练集和验证集均由用户提供，各为独立 UTF-8 JSONL 文件，每行格式：

```json
{"query": "如何减少模型训练时的显存占用？", "positive": "减小批大小和序列长度可以降低训练显存开销。"}
```

- 每行必须为 JSON 对象，query 和 positive 为去除首尾空白后非空的字符串。
- 空行可跳过；格式错误给出文件名和行号。额外字段不送入训练器。
- 完全重复的数据对去重；训练集至少包含两个不同查询和两个不同文档。
- 验证集至少包含两个不同查询和两个不同文档，允许一个查询关联多个正例。
- 训练和验证中出现相同查询则报错，避免直接的数据泄漏。
- 验证集为可选项；未提供时明确提示没有评估结果，不自动拆分或虚构指标。
- 数据加载和参数检查在模型下载前完成；输出目录已有内容时拒绝覆盖。

批内其他文档作为负例，使用库提供的无重复采样器避免相同文本进入同一批。
batch size 至少为 2，丢弃不足完整批次的尾批；训练前确认至少存在一个
合法完整批次，避免无训练步骤却保存成功。用户需保证不同查询的文档不是
彼此的未标注正例；近重复和语义层面的假负例需要数据清洗解决。

## 训练与模型产物

命令行接受训练集、可选验证集、基础模型、输出目录、batch size、epoch 数、
学习率、最大序列长度、随机种子和设备参数。数值参数检查合法范围与有限性。
按用户补充要求，默认设备选择优先使用可用 CUDA GPU，否则使用 CPU；
显式要求 CUDA 但不可用时给出错误。当前环境的 CPU 验证不能代替 GPU 实测。

默认 Nomic 模型使用 `search_query: ` 和 `search_document: ` 前缀。
其他模型按其模型说明配置查询与文档前缀，避免静默沿用 Nomic 设置。
需要自定义模型代码时，由显式参数开启 trust_remote_code。
训练、评估和文档中的推理示例使用一致的前缀和最大序列长度。

输出目录包含可由 SentenceTransformer 加载的最终模型，以及记录基础模型、
前缀、超参数和依赖版本的运行配置。使用固定种子，日志输出训练损失。
不承诺不同设备之间逐位复现，也不承诺训练后检索指标必然提升。

## 评估

在同一个独立验证集上分别评估训练前和训练后模型。
候选语料为验证集 positive 文档去重后的集合；同一 query 的多个 positive
合并为相关文档集合。使用余弦相似度，输出 Recall@1、Recall@5、Recall@10
和 MRR@10，保存为 JSON，并记录查询数和候选文档数。
这些指标只代表该验证语料上的效果，不代表整个生产知识库的检索质量。

## 验收

1. 无模型下载即可运行的数据测试覆盖非法行、空值、重复数据和训练/验证泄漏。
2. 命令行帮助可运行，非法参数和已有输出目录给出明确错误。
3. 在训练依赖可用时，用本地小模型和少量独立样本执行一次训练，确认权重变化、
   模型保存后可重新加载、向量维度正确且数值有限，评估结果成功写入。
4. 若环境无法运行真实训练，明确记录未验证项，不把数据测试等同于训练成功。
5. 使用说明提供环境安装、数据格式、训练命令和本地模型编码示例，并说明正式
   微调仍需要用户提供真实数据；接入现有检索属于后续工作，需要重建文档向量。
